# S2 — 写作风格与内容规范

> 适用范围：仓库内所有 `.md` 文档的正文内容。

## 1. 读者优先的 Divio 四分类

每篇文档**只承担一个主要意图**。混写是本仓库当前最大的可读性问题。

| 类别 | 意图 | 读者读完能做什么 | 禁止包含 |
|---|---|---|---|
| **教程 Tutorial** | 学习 | 从零跑通第一个用例 | 原理讲解、完整 API 清单、选项对比 |
| **操作指南 How-to** | 完成具体任务 | 完成一个明确目标 | 概念铺垫、安装重复、背景故事 |
| **参考 Reference** | 查阅 | 查到某个值/签名/行为 | 叙事、"为什么这么设计"的长篇 |
| **解释 Explanation** | 理解 | 理解某机制为何如此 | 逐步操作步骤、参数全表 |

**判定方法**：如果一段话可以原样搬到另一篇文档而不影响任一文档的可读性，它就属于**参考**内容，应该被抽到 `docs/reference/` 或代码 Javadoc 中。

## 2. 语言风格

### 2.1 基本要求

- **第二人称 + 现在时 + 主动语态**：「你运行 `mvn verify`」而不是「应当执行 mvn verify 命令」。
- **面向结果开场**：首段说清"读完你能做到什么"，而不是"本文介绍 XXX"。
- **中文正文 + 英文标识符**：技术术语、类名、命令、配置键保持英文原文，不翻译（如「路由拦截」不写「路由拦截器路由」）。
- 句子尽量短。一句话超过 3 个分句就拆开。

### 2.2 禁止事项

| 禁止 | 原因 | 替代 |
|---|---|---|
| 「简单来说」「众所周知」「其实」 | 无信息量的填充语 | 直接说结论 |
| 「我们认为」「我个人觉得」 | 主观语气，掩盖事实 | 给出依据和适用范围 |
| 「大概」「可能」「应该是」 | 不确定的断言 | 明确条件，或标注为待确认并写进 issue |
| 「请注意……（重复三段）」 | 重复强调等于没强调 | 集中到"注意事项"小节 |
| 整段中文长句不分句 | 难以扫读 | 拆句、列表化 |
| 中英标点混用（英文句用中文句号） | 排版不一致 | 中文段落用中文标点；代码/命令内保持原样 |
| 章节标题带书名号《》 | 无必要 | 直接用名称 |

### 2.3 语气：承认复杂性

当一个步骤确实有多个活动部件（moving parts），**必须**说明，而不是假装简单：

> 该步骤涉及三个线程：测试线程、Playwright 派发线程、异步消费线程。完整时序见 `docs/architecture/Java-Playwright-1.62-网络API分层指南.md`。

## 3. 术语一致性

### 3.1 固定术语表

下列词在本仓库**必须**使用左列写法，全仓库统一：

| 使用 | 避免 | 含义 |
|---|---|---|
| 框架 | 库 / 工具集 | `pw_automation_framework` 本身 |
| 测试工程 | 测试项目 / 自动化工程 | `test-automation` 仓库 |
| 路由拦截 | 网络拦截 / hook 拦截 | `pw-route` 的 monitor/mock/modify/delay 能力 |
| 声明式 | 声明式 DSL / 注解式（泛指） | `RouteDsl` 的编程方式 |
| 用例 | 测试用例 / scenario（指 Gherkin 文件时用"场景"） | 一条测试场景 |
| 步骤定义 | step def / 步骤实现 | Gherkin step definition |
| 元素选择器 | 定位器 / selector | Playwright locator |
| 报告 | 汇总报告 / 集成报告 | Serenity 兼容报告 |
| 门禁 | 校验 / 检查点（泛指时用"检查"） | CI 中失败即阻断的检查 |
| 漂移 | 不同步 / 不一致 | 文档与源码事实不一致 |

### 3.2 命名约定在正文中的体现

- 模块一律用目录名：`core` / `web` / `api` / `route` / `codegen` / `reporting`。
- 配置键写全名，如 `` `route.capture.all.type` ``，不写"那个 type 配置"。
- 类名写全限定名时用最短可辨识形式：`` `framework.web.page.PageObject` ``。

## 4. 代码示例规范

### 4.1 硬性要求

- **示例必须可运行**。发布前在一个干净环境跑过一次；写不出来说明这个 API 还没验证过，**不要写进文档**。
- 每个代码块**必须**指定语言：```` ```java ```` / ```` ```bash ```` / ```` ```xml ```` / ```` ```yaml ```` / ```` ```text ````。
- 代码块**必须**有语言标注，禁止裸 ```` ``` ````。
- 示例中**不得**出现真实的凭据、账号、内部主机名、真实客户数据。用占位符：`"DBB_TEST_USER"`、`"https://example.internal"`。
- 展示 API 全貌时用省略号可以，但**不能**省略掉让示例失去可编译性的部分。

### 4.2 示例的组织

长示例按"能跑起来的最小单元"给，不给"演示了十个 API"的巨型块。超过约 40 行就拆成多段并解释每段。

每个关键示例前**必须**有一句话说明它**证明了什么**：

```java
// 断言响应体前必须等 requestfinished，body 在 response 事件时可能尚未完整下载
Request fin = page.waitForRequestFinished(
    r -> r.url().contains("/api/order/submit"),
    () -> page.getByRole(AriaRole.BUTTON, new Page.GetByRoleOptions().setName("提交")).click());
```

### 4.3 命令块

- 标明**执行目录**（根目录 / 模块目录），因为多模块工程里目录错了命令就会失败。
- 标注**预期输出**，便于读者自查：

```bash
# 在仓库根目录执行；预期输出 "Doc drift check PASSED"
pwsh tools/check-doc-drift.ps1
```

- 涉及 CI 的命令注明触发的工作流名与文件路径。

## 5. 表格规范

- 表格用于**结构化对比**（参数、返回值、选项、前置条件），不用于排版美观。
- 表头必须明确：`| 参数 | 类型 | 默认值 | 说明 |`，不要用「名称」「备注」这类模糊词。
- 默认值列写**实际值**，不写"无"——写 `—`（表示不适用）与「无默认值」要区分开。
- 单元格内容尽量短；超过 80 字符的说明应移到表格下方正文。
- 表格前后必须有引出句，**不允许**表格直接跟标题。

## 6. 图表规范

- 每张图**必须**有图注（紧邻图片的一段文字），并写明"看图要点"——3 条以内，结论式。
- 图注不重复图里的文字，而是**解释图表达不了的关系**。
- 时序图必须标出**线程边界**（本项目高频坑点：Playwright 回调不在测试线程）。
- 图片 alt 文本写成完整句：`![一次成功请求的时序 × Playwright Java API 分层](assets/request-lifecycle-layers.svg)`。
- 优先 SVG；PNG 仅用于真实界面截图。

## 7. 链接规范

- 站内链接用相对路径；跨仓库写仓库名 + 路径。
- 链接文本**必须能独立理解**，禁止「点击这里」「详见」。
  - ✅ `[Route DSL 使用指南](../architecture/route-dsl-guide.md)`
  - ❌ `[点击这里](../architecture/route-dsl-guide.md)`
- 指向外部文档时说明**该链接为什么会腐坏**（如"Playwright 官方 API 文档，1.62 版本"），便于未来读者判断可信度。
- 一个文档被移除时，**必须**同时更新所有指向它的链接——这是 `tools/check-doc-drift.ps1` 门禁的职责范围。

## 8. 结构规范

### 8.1 标题层级

- 每篇文档**只有一个** H1，等于文档标题。
- 不跳级：H1 → H2 → H3，不出现 H2 后直接 H4。
- 编号标题用于**需要被引用顺序**的文档（架构方案），一般文档用无编号标题。

### 8.2 章节必备内容

| 章节类型 | 必备内容 |
|---|---|
| 开篇 | 一句话说明本文覆盖什么 + 读完能得到什么 |
| 涉及前置条件 | 显式列出（版本、环境、依赖服务） |
| 涉及命令 | 标注执行目录与预期输出 |
| 涉及配置 | 给出键名、默认值、取值优先级影响 |
| 涉及异常/失败 | 给出错误信息样例与处置 |
| 结尾 | 相关文档链接；必要时给出"下一步" |

### 8.3 段落长度

- 段落超过 5 行**必须**改为列表或表格。
- 列表每项不超过 2 行；超长则拆条。

## 9. 敏感信息

文档**不得**包含：

- 真实凭据、token、账号口令；
- 内部环境的真实主机名与 IP；
- 真实客户数据或未经脱敏的请求/响应报文；
- 生产库的连接串。

需要示意时使用占位符并显式标注「示例值」。此条与仓库的日志脱敏基线（`SanitizingMessageConverter`）是同一原则在文档侧的延伸。

## 10. 自检清单

- [ ] 文档只承担一个主要意图（Divio 四分类之一）
- [ ] 首段说清读者能得到什么
- [ ] 术语符合 §3.1 术语表
- [ ] 所有代码块有语言标注且可运行
- [ ] 所有示例无真实凭据与真实数据
- [ ] 命令标注了执行目录与预期输出
- [ ] 表格有明确表头与真实默认值
- [ ] 图片有图注与独立可懂的 alt 文本
- [ ] 站内链接为相对路径且文本可独立理解
- [ ] 无填充语、无主观语气、无"请注意"堆砌

pw Agent Driver —— 浏览器指挥与 Step 代码生成

把「业务流意图 → 浏览器执行 → 元素定位 → Step 业务代码」串成一条企业级流水线。参照 Microsoft Playwright MCP 的快照/ref 驱动机制，吸收其「非安全边界」教训，在本框架内做成快照即真相、确定性执行、AI 只提候选、生成代码后运行时无 LLM的闭环。

1. 设计目标与五条企业级原则

目标：用户以业务流程（自然语言 / 录制骨架 / DSL）描述要做什么，框架指挥浏览器逐步执行、自动发现并验证元素定位器、生成可提交、可回归、可维护的 Step 业务代码（Feature + Glue + Page Object）。

原则含义与判定标准
P1 · 快照即真相浏览器状态只来自运行时 a11y 快照（role/name/ref + 候选 selector），禁止凭模型记忆或 CSS 猜测写定位器。每一步「先观察、后动作、再回读」。
P2 · 确定性执行LLM 只产出「受 schema 约束的意图与候选」，执行由确定性 StepDriver + 原语通道承担。同一 StepPlan 在 CI 重复运行结果一致（幂等可重放）。
P3 · AI 与运行时分离生成 Step 代码落库后，回归运行时零 LLM 依赖（借鉴 MCP 官方理念：committed tests are the durable artifact）。LLM 只存在于「设计期/生成期」。
P4 · 最小权限与真边界MCP 官方明示「不是安全边界」；本设计把边界做实：原语分级（读/写/高危）、凭据不进 AI 通道、无自由代码执行、上下文隔离、来源白名单。
P5 · 全链路可观测每步带 trace（步骤 id、快照指纹、定位器来源、耗时、结果），失败即收敛（复用 F1），产物可回放、可审计。
与「生成稳定代码」的关系：稳定性来自三条链路 —— ① 定位器经 DOM 唯一性断言 + 灰度回注后才成为代码里的常量；② 生成物编译 + 冒烟执行双验证后才落库；③ 生成代码内嵌 trace 注释（来源、验证时间、指纹），可追溯。

MCP 机制（源码事实 @0.0.83）借鉴本设计强化
a11y 快照驱动：browser_snapshot 返回可达性树，支持 target（子树）、depth（深度限制）、boxes（viewport 坐标 [box=x,y,w,h]，默认关）；官方明示「基于截图不能做动作，用 snapshot」同构 SnapshotTree：scope（viewport/全页/子树）+ 深度限制节点同时注入候选 selector（ref 仅供当轮交互；selector 供落库），附 DOM 唯一性指纹
ref 生命周期：target 参数「Exact target element reference from the page snapshot, or a unique element selector」；ref 只在单快照内有效同规则：交互只用当轮 ref，代码永不提交 ref「ref → locator」做成强制流程：browser_generate_locator（testing caps，元素→测试定位器）即 MCP 自带的转换原语，我们将其固化为 CandidateValidator 必经环节
闭环循环：Snapshot → Interact(target=ref) → Re-snapshot；动作后 settle 500ms（timeouts.settle）。实现细节（coreBundle 实测）：waitForCompletion（backend/utils.ts）在动作后 waitForTimeout(settleMs)，同时监听 request 事件；若期间触发 navigation request 则继续等导航完成（Promise.race，5s 兜底），再补一次 settleStepDriver 每步走完整闭环；Verify 阶段对齐该语义：动作后「静默窗口 + 导航感知」而非固定 sleep增加期望态校验（expect 条件，对齐 testing caps 的 browser_verify_element_visible/verify_text_visible/verify_value），失败即收敛并产出最小失败现场
原语工具集（0.0.83 全量 30+ 工具）：core 组含 click/type/fill_form/select_option/hover/press_key/navigate/evaluate/find/drag/drop/wait_for/emulate_media/file_upload/dialog/console/network/resize/run_code_unsafe；caps 分组：tabs / install / network（route+offline）/ storage（cookie+local/session storage+storage-state）/ pdf / vision（坐标鼠标）/ devtools（录制/trace/video/annotate）/ testing（generate_locator+verify_*）/ config（get_config）同构 BrowserCommandChannel 原语集，按 caps 语义分组每个原语声明幂等性 + 权限级 + 失败语义；写原语默认需授权；能力开关按组进 ConfigRegistry（对齐 browser_get_config：MCP 也做 CLI+env+config 文件三层合并，与我们 ConfigReader 层序同构）
录制骨架：browser_start_recording / browser_stop_recording（devtools caps，录用户手动操作→Playwright 代码）；codegen 配置支持 typescript/python/java/csharp 语言目标。实现细节（coreBundle 实测）：语言生成器集合 languageSet()（isomorphic/codegen/languages.ts）含 JS/Python/Java/C# 生成器；SDKLanguage = tEnum(["javascript","python","java","csharp"])；Java 生成器提供两模式：Library（id=java）与 JUnit（id=java-junit）；Java locator 输出形态为 getByRole(AriaRole.BUTTON, new GetByRoleOptions().setName("..."))、filter 用 new FilterOptions().setHasText(...)录制→代码链路直接采用；Java 两模式（Library/JUnit）作为生成层模板基线录制输出对接到我们 Codegen 录制套件，语言目标固定 java（对齐 JUnit 模式语义，天然匹配框架 JUnit5）；产物升级为三层（Feature/Glue/PO），MCP 只产单文件代码
browser_run_code_unsafe：任意 Playwright 代码，官方描述「executes arbitrary JavaScript in the Playwright server process and is RCE-equivalent」默认禁用；仅本地调试模式可开开启需双开关（config + JVM 属性），每次调用留审计日志（调用者/脚本摘要/时长）
官方声明「不是安全边界」：README 原文 —— --allowed-origins 「does not serve as a security boundary and does not affect redirects」；secrets 注释「a convenience and not a security feature」；allowUnrestrictedFileAccess 注释「not a secure boundary」不照搬该声明本设计把安全做成真边界（见 §5）：allowed-origins → 我们加 redirect 链终点评验；secrets 明文替换 → 我们做脱敏通道（不进 AI 上下文）；文件访问 → 归入红线管控
隔离/持久 profile：persistent 为默认（headed，profile 按 workspace-hash 自动分目录、单实例互斥——并发 client 需 --isolated 或独立 user-data-dir）；isolated 每会话 fresh，登录态靠 --storage-state / contextOptions 注入；idle-timeout headless 默认 1h、headed 永不会话策略沿用策略按流程声明（ConfigReader 键），默认 isolated + 显式 storage-state；并发沿用 ConcurrencyGate 分区语义
上下文注入点：createConnection(config, contextGetter) —— 外部可注入 BrowserContext 提供者。实现细节（coreBundle 实测）：有 contextGetter 时包装为 SimpleBrowser(await contextGetter())，该 class 的 newContext() 直接 throw（"Creating a new context is not supported"）——外部 context 为单实例只读注入；无注入时走 createBrowserWithInfo（persistent 默认 / isolated 每会话 fresh）企业集成点直接采用；对外部 context 只读注入语义与我们的会话所有权一致对应我们 BrowserStartupImpl / SessionStore 作为 context 提供者注入 StepDriver，登录态/环境隔离复用现有会话设施；注入后禁止 context 新建（同 SimpleBrowser 语义）
探索用 MCP、回归用提交的测试（committed tests are the durable artifact, make the agent optional at regression runtime）核心理念直接采用生成物落库后 CI 运行零 LLM/零 agent；LLM 仅在生成期出现
结论：0.0.83 证明「快照驱动 + 观察-动作-回读 + 工具原语化 + 录制→代码」是让 AI 稳定操作浏览器的正确范式；它把安全声明为边界外（allowed-origins 不防 redirect、secrets 非安全特性、run_code_unsafe RCE 等价）。我们取它的协议与工具思想，补上企业级要的验证、权限、回注、可观测四件套。

4.2 SnapshotTree —— 快照协议

每次快照返回一棵 a11y 语义树；交互节点同时携带：ref（当轮唯一、DOM 变化即失效）、候选 selector（role/name/text/结构，供验证与落库）、唯一性指纹（当前 DOM 下唯一命中的哈希证明）。

SnapshotTree ::= Node*
Node ::= { ref: "e12", role: "button", name: "新建订单",
           candidates: [getByRole('button',{name:'新建订单'}),
                        getByText('新建订单'), ...],
           fingerprint: sha256(unique-match-evidence),
           children: Node* }
机制规则
ref 生命周期ref 仅在本次快照内有效；动作后必须 Re-snapshot 拿新 ref。代码生成永不使用 ref（同 MCP 官方规则：ref 是观察句柄，不是测试选择器）。
候选 selector 注入从 RoleElementPicker（语义）/ SelectorStability（结构修正）/ CodegenFacts（历史候选）三源合成候选集，按 CodegenScorer 打分排序。
视口与触底默认视口内快照；需要全页/子树时显式 scope。懒加载区域由 StepDriver 显式滚动步补齐（对齐浏览器「先观察后动作」）。
脱敏输入框 value 与密码类内容默认打码（••••）；敏感步骤由 IntentEngine 声明 SensitiveStep，快照与 trace 均不落原文。
快照指纹每步快照取语义哈希 → 幂等判定（同状态重复执行跳过）+ 失败现场比对（与期望态 diff 出最小差异）。

4.3 意图翻译与 StepPlan

三源归一为受 schema 约束的 StepPlan；schema 即幻觉防护网（未知 ActionType / 缺 Target / 缺 Expect 直接拒绝）。

意图源机制适用
录制骨架现有Codegen 录制一次业务流程 → 结构化动作序列作为确定性骨架；LLM 只做「补全泛化」（变量参数、断言、异常分支）。核心回归路径（确定性最高，首选）
自然语言新增LLM 翻译「登录→进入订单管理→新建订单」→ StepPlan；输出经 schema 校验 + 可执行性预检（首步 navigate 是否可达）后放行。探索新路径 / 一次性场景
结构化 DSL新增YAML/JSON 步骤声明（action/target/params/expect），逐条校验后直接执行；零 LLM 依赖。稳定流程的显式表达 / CI 注入
StepPlan schema（示例）：
step:
  id: S1
  action: click            # navigate|snapshot|click|type|fill|select|press_key|assert_state|mock|tab
  target: { ref: e12, candidate: "getByRole('button',{name:'新建订单'})" }
  params: { value: null, key: null, option: null }
  expect: { type: url_contains, value: "/order/new", timeoutMs: 8000 }
  sensitive: false
  trace: { source: RECORDING|LLM|DSL, planId, fingerprint }

4.4 定位器四梯队与生命周期

梯队来源验证方式产出
① 录制Codegen 录制已产定位器（RoleElement/两步拾取）直接可信 + 每次运行回归校验稳定常量
② 语义RoleElementPicker 按 role/name 解析DOM 唯一性断言（单节点命中）候选 selector
③ 结构SelectorStability 修正（Radix 夹心、动态属性等）结构指纹 + 唯一性断言候选 selector
④ AI 兜底LLM 读快照+可达性树提出候选必须过唯一性断言；人工/录制回注确认后才落库（灰度比例开关）候选 → 回注为稳定常量
AI 候选铁律：AI 产出的一律视为「未验证候选」。候选进库必须满足三条件 —— ① DOM 唯一性断言通过；② 冒烟步骤执行成功 ≥N 次（默认 3）；③ trace 记录提出者与验证证据。任何一条不满足即回退上一梯队。

4.5 稳定代码生成（三层产物）

生成物与代码仓同构，生成后立即进入与手写代码相同的评审/编译/运行管线：

产物内容稳定性保障
Feature业务语言场景（Given/When/Then），来源于 StepPlan 的业务化改写人工可读、可评审
Glue step@Given/@When/@Then 方法，仅做参数解包 + 调 Page Object无定位器逻辑（单一职责）
Page Object + 业务方法定位器常量（已验证回注）+ 业务方法（登录/新建订单…）定位器全部来自回注库；方法带 trace javadoc（来源/指纹/验证时间）

验证管线：模板生成 → 编译（checkstyle 同规）→ 冒烟执行（生成场景跑 1 遍）→ 落库。落库后即普通代码，回归运行时零 LLM（P3）。

5. 安全红线（借鉴 MCP 教训，做成真边界）

MCP 官方明确：它不是安全边界（allowed-origins 不防 redirect、secrets 非安全特性、run_code_unsafe 是 RCE）。本设计的立场相反：安全红线由框架本身强制，每条红线有对应的实现对策与验证手段。

红线（不可违反）设计对策
R1 · 凭据与敏感值不进 AI 通道敏感步骤（SensitiveStep）的取值经脱敏通道注入：LLM 上下文只见 ••••；type/fill 的敏感值仅存内存一次、用完即弃；快照与 trace 不落原文；storage_state 文件不进 AI 上下文。（依据：MCP 的 secrets 是明文替换，官方注释明示「a convenience and not a security feature」——我们不用该机制，改做真脱敏通道）。
R2 · 无自由代码执行run_code_unsafe 默认禁用；开启需 config 键 + JVM 属性双开关（对齐 v2.23.5 收敛层序），且仅限本地调试；每次调用落审计日志（调用者、脚本摘要、时长）。
R3 · 来源白名单是真边界navigate 前校验目标 origin ∈ 流程声明的 allow-list；同时校验 redirect 链最终落点——README 0.0.83 官方原文：--allowed-origins 「does not serve as a security boundary and does not affect redirects」，我们正是补上 MCP 缺失的 redirect 校验；blocked-origins 优先于 allowed-origins。
R4 · 上下文隔离默认 isolated context（每流程 fresh，Cookie/localStorage 零残留）；持久登录必须显式声明 storage-state 键；并发场景沿用 ConcurrencyGate 分区语义。
R5 · 写/高危原语授权门禁click/type/submit 等写原语与高危原语默认经授权点（人工确认或流程 allow-list，对齐现有按需确认模式）；授权记录进 trace。（依据：MCP 的 elementSchema 官方定义即「Human-readable element description used to obtain permission to interact with the element」——它的授权姿势是让 client 基于人读描述确认，我们将其升级为框架级强制授权点）。
R6 · AI 无执行权AI 输出仅两类：受 schema 约束的 StepPlan、未验证候选 selector。两者都过确定性校验层（§4.3/§4.4）后才生效；AI 永远不能直接调用浏览器原语。
R7 · 快照脱敏输入框 value、密码、token 类节点默认打码；脱敏开关可由步骤级或流程级声明覆盖（默认开）。
R8 · Mock 与数据不泄漏route_mock 与会话生命周期绑定，收尾强制撤销（沿用 Route 收敛语义）；测试数据走最小权限账号/靶场（对齐 RouteTestBed 模式），不碰生产凭据。
R9 · 全量审计每原语/每步/每次 LLM 调用计 AgentTrace：原语、参数摘要（敏感字段打码）、来源、耗时、结果、快照指纹；汇入自研 Report，可导出可回放。
红线验收标准：每条红线有单元测试/架构测试（ArchUnit 级）守护——例如「AI 候选未过验证器不得进回注库」「敏感键在 trace 中出现即测试失败」，防止后续迭代回退。

DBB 自动化测试框架 · 使用指南

基于 Playwright 驱动浏览器、Serenity BDD + Cucumber 组织用例与报告，内置声明式网络拦截（monitor / mock / modify / delay）、日志脱敏与并发执行的企业级多模块测试框架。

JDK 21Maven 多模块 Playwright 1.62Serenity 4.3.4 Cucumber 7.34JUnit 4
本指南只讲怎么用（不含实现原理）。示例中的接口路径（/api/users、/api/login 等）对应仓库内 route-demo-service 演示后端，可直接拿来练手。

1框架概览

这是一套「UI + 接口」一体的自动化测试框架。你用 Cucumber 写业务用例（Gherkin），用 Playwright 操作页面，用框架自带的 Route DSL 拦截/伪造网络请求，Serenity 自动生成图文报告。

2工程结构（用例工程约定的目录）

框架仓库只放「能力模块」；你的业务用例放在测试工程里。约定目录如下：

test-automation/
├─ src/test/resources/
│  ├─ features/                 # Gherkin 用例（.feature）
│  │  └─ users/user-list.feature
│  ├─ nls/                      # 多语言元素名（@RoleFile 指向）
│  │  └─ users.nls.json
│  ├─ mocks/                    # Route / Mock 规则配置（可选）
│  └─ serenity.conf             # 框架配置（见第 8 节）
└─ src/test/java/…/
   ├─ runners/                  # Cucumber 启动类（CucumberTestRunnerIT）
   ├─ steps/                    # Step Definitions（@Given/@When/@Then）
   └─ pages/                    # Page Object（继承 BasePage）
约定优于配置：feature 放 src/test/resources/features；Step 与 Page 放 src/test/java 下同包结构；Runner 通过标签（tags）决定跑哪些用例。

3快速开始

前置：JDK 21、Maven 3.9+、可联网装浏览器。

# 1) 首次：安装 Playwright 浏览器（chromium）
mvn exec:java -Dexec.mainClass=com.microsoft.playwright.CLI -Dexec.args="install chromium"

# 2) 构建 + 全量校验（含 SpotBugs / Checkstyle / 汇总报告）
mvn -B verify -DskipITs

# 3) 只跑测试工程（自动带上各框架模块）
mvn -pl test-automation -am test

4如何写用例

一个用例由三层组成：Feature（做什么）→ Step（怎么做）→ Page（在哪个页面做）。三层各司其职，业务可读、代码可维护。

① Feature 文件（Gherkin）

用业务语言描述场景，不写任何实现细节。中文/英文皆可，团队统一即可。

@smoke
Feature: 用户管理

  Background: 打开用户列表
    Given 打开用户列表页

  Scenario: 查询用户列表
    Then 用户列表应包含 3 条记录

  Scenario: 查询不存在的用户
    When 查询用户 ID 999
    Then 结果应为空

  @route
  Scenario: 列表接口异常时页面给出提示
    Given 列表接口返回 500
    When 刷新用户列表页
    Then 页面应显示"加载失败"提示

② Step Definition（把中文步骤接到代码）

放在 steps/ 包。一个 Step 只做「调用页面对象 + 断言」，不写选择器。

package steps;

import org.assertj.core.api.Assertions;
import io.cucumber.java.en.*;
import pages.UserListPage;

public class UserSteps {

    // 页面对象按需创建；框架自动注入当前线程的 Page/Context
    private final UserListPage userListPage = new UserListPage();

    @Given("打开用户列表页")
    public void openUserList() {
        userListPage.navigateTo("/demo/users");
    }

    @Then("用户列表应包含 {int} 条记录")
    public void shouldContain(int count) {
        userListPage.waitForRows(count);
        Assertions.assertThat(userListPage.userRows.size()).isEqualTo(count);
    }

    @When("查询用户 ID {int}")
    public void queryUser(long id) {
        userListPage.queryById(id);
    }
}
参数化步骤：Cucumber 内置 {int}、{string}、{word} 等占位符，直接映射为方法参数，无需手工解析。

③ 在 Step 里做接口拦截（Route）

需要"让接口返回 500 看页面表现"时，在该步骤里用 RouteDsl 注册规则（详见第 6 节）：

@Given("列表接口返回 {int}")
public void listApiReturns(int status) {
    // getPage() 取当前线程的 Page；完整 DSL 见第 6 节
    RouteDsl.on(getPage())
        .api("/api/users")
        .mock().status(status).body("{\"error\":\"boom\"}").contentType("application/json")
        .register();
}

5页面对象与元素定位

页面对象继承 BasePage，把"元素"声明成字段。运行期框架自动绑定当前线程的 Page/Context，Step 直接点字段操作，不接触 Playwright 原生选择器。

最小页面对象

package pages;

import com.microsoft.playwright.options.AriaRole;
import com.hsbc.cmb.hk.dbb.automation.framework.web.page.engine.BasePage;
import com.hsbc.cmb.hk.dbb.automation.framework.web.page.element.*;

@RoleFile("nls/users.nls.json")          // 该页面的多语言元素名文件（声明一次）
public class UserListPage extends BasePage {

    @RoleElement(role = AriaRole.HEADING, level = 1, key = "title")
    public PageElement title;

    @RoleElement(role = AriaRole.LISTITEM)
    public PageElementList userRows;       // 一组元素

    @RoleElement(role = AriaRole.BUTTON, key = "refresh")
    public PageElement refreshButton;

    public void waitForRows(int expected) {
        userRows.waitUntilCount(expected); // 带重试/诊断的等待
    }

    public void queryById(long id) {
        // 语义定位：CSS 属性选择器（数字 ID 无 NLS key 时直接表达）
        element("[data-user-id='" + id + "']").click();
    }
}

BasePage 常用 API（Tier-1 用户接口）

方法说明
element(String selector)定位单个元素，返回 PageElement（含重试/诊断/截图）
elements(String selector)定位一组元素，返回 PageElementList
locator(String selector)定位原始 Locator（仅在需要框架未封装能力时用）
navigateTo(String url)导航到相对/绝对地址（自动等页面加载）
refresh() / back() / forward()页面刷新 / 后退 / 前进
getPage() / getContext()取当前线程的 Page / BrowserContext
switchToPage(...) / waitForNewPage(...)多页（新标签页）切换与等待
waitForDownload(...)等待并获取下载文件

定位策略：优先「角色 / 语义」，不要写 CSS/XPath

@RoleElement 支持两类策略，二选一（设置语义属性后 role 被忽略）：

策略写法等价于
角色 + 多语言@RoleElement(role = AriaRole.BUTTON, key = "signIn")按角色 + NLS 名称，支持多语言
@RoleElement(role = AriaRole.BUTTON, name = "Sign in")按角色 + 字面名称（NLS 无 key 时用）
语义定位@RoleElement(text = "Submit")getByText
@RoleElement(label = "Username")getByLabel（定位关联 input 控件）
@RoleElement(placeholder = "搜索")getByPlaceholder
@RoleElement(testId = "user-row")getByTestId
@RoleElement(altText = "Company logo")getByAltText
@RoleElement(title = "帮助")getByTitle

进阶属性：level（标题层级）、exact（精确/子串）、disabled/pressed/expanded（三态：ANY/YES/NO）、frame = {"iframe[name=\"x\"]"}（iframe 内元素）。

推荐：优先用 pw-codegen 的交互式拾取器点选元素，自动生成 @RoleElement 草稿（含 NLS key），人工 review 后合入。

6Route 网络拦截怎么用

Route 让你在不改后端的前提下，声明式地观测、伪造、改写、延迟浏览器发出的 HTTP 请求。它挂在 BrowserContext 上，按 context 隔离，天然并发安全。

四种能力（一规则一能力）

能力作用会不会影响请求
MONITOR观测：记录请求/响应，做状态码 / JSONPath / 体 / 表单断言否（fail-open，放行）
MOCK伪造响应：静态 body/status，或取真实响应后改字段是（交付你给的内容）
MODIFY_REQUEST改写请求：请求头 / method / 请求体字段是（后端看到的是改后的）
DELAY延迟放行：模拟慢网络 / 超时否（只是晚点放行）

基本骨架

import com.hsbc.cmb.hk.dbb.automation.framework.route.dsl.RouteDsl;

AutoCloseable handle = RouteDsl.on(page)     // 也可 RouteDsl.on(context)
    .api("/api/users/**")                    // URL 通配 pattern
    .monitor()                               // 选择能力：monitor / mock / modifyRequest / delay
        .expectStatus(200)
        .expectJsonPath("$.length()", 3)
    .register();                             // 提交注册，返回可精确注销的句柄
// ... 执行业务步骤 ...
handle.close();                              // 精确注销（幂等）；场景结束框架也会自动清理
两种收尾写法等价：.register() 立即注册；级联写法 …done().start() 效果相同（start() 也返回句柄）。
DELAY 段没有 register()，请用 .api(p).delay(3).done().start();。

匹配条件（收窄规则命中范围）

在 api(pattern) 之后、能力之前或之后链式声明，多个条件同时满足才命中：

RouteDsl.on(page)
    .api("/api/login")
        .onlyApi()                    // 只匹配 xhr/fetch
        .matchMethod("POST")          // 精确 method
        .matchHeader("X-Env", "sit")  // 请求头精确
        .matchQuery("locale", "zh_CN")// query 精确
        .matchContentType("json")     // content-type 包含
        .matchBodyRegex(".*username.*")// 请求体正则
        .onlyMainFrame(true)          // 只主框架（默认）
    .mock()…

条件不满足的请求自动 fallback 到下一个匹配的规则，不会"吞掉"请求。

7Route 实战配方

MONITOR观测并断言真实响应

RouteDsl.on(page)
    .api("/api/users/**")
    .monitor()
        .expectStatus(200)
        .expectJsonPath("$[0].role", "USER")
        .expectBodyContains("Alice")     // 文本/XML/HTML 均可
        .timeout(10)                     // 断言等待窗口（秒，0=不超时）
    .register();
默认即采集：.monitor() 段默认记录请求/响应（响应体按 64 KiB 截断）。要关闭用 .capture(false) / .captureBody(false)。

MOCK静态伪造响应

RouteDsl.on(page)
    .api("/api/auth/login").onlyApi().matchMethod("POST")
    .mock()
        .status(200)
        .body("{\"token\":\"mock-token\",\"message\":\"ok\"}")
        .contentType("application/json")
        .header("X-Mocked", "true")
    .register();

也支持从 classpath 读模板、对象转 JSON、二进制保真：

// 读 classpath 模板 + 覆盖字段
.mock().mockBodyFromFile("mocks/login-template.json", Map.of("token", "t-x"));
// 对象自动转 JSON
.mock().mockBody(Map.of("code", 0, "msg", "ok"));
// 二进制（图片 / protobuf / gzip）——逐字节保真，不走字符串往返
.mock().mockBody(new byte[]{1,2,3}).contentType("application/octet-stream");

MOCK拦截真实响应后改写

// 取上游真实响应，改字段后再交给前端
RouteDsl.on(page)
    .api("/api/users")
    .mock().interceptResponse()
        .replaceField("$[0].name", "MOCKED")
        .replaceFields(Map.of("$[1].role", "ADMIN"))
    .register();

// 条件改写：仅当 status 为 PENDING 时才把 status 改成 SHIPPED
RouteDsl.on(page)
    .api("/api/users/**")
    .mock().interceptResponse()
        .when("$.status", "EQUALS", "PENDING").thenSet("$.status", "SHIPPED")
    .register();
互斥规则：interceptResponse()（取真实响应）与静态 status/body/header 不能同时用，配置期即报错。

MODIFY_REQUEST改写请求

RouteDsl.on(page)
    .api("/api/users")
    .modifyRequest()
        .setRequestHeader("X-Env", "mock")
        .removeRequestHeader("X-Debug")
        .modifyRequestBody("$.role", "ADMIN")        // JSONPath：存在即改，缺失即建
        .addRequestBodyField("$.tags[]", "vip")
        .modifyFormField("channel", "app")           // 表单（urlencoded）
    .register();

// 改 method（内部走 fetch+fulfill）
.modifyRequest().modifyMethod("PUT")

DELAY模拟慢网络

// 固定延迟 3 秒后放行（单位：秒）
RouteDsl.on(page).api("/api/slow/**").delay(3).done().start();

// 随机延迟：每次请求在 [1,5] 秒内随机
RouteDsl.on(page).api("/api/pay/**").delay(1).randomDelay(1, 5).done().start();
DELAY 用 .done().start() 收尾（它没有 register()）。单请求延迟上限 30 秒。

采集数据：查看与消费

// 非消费式：随时看该 context 采集到了什么（幂等）
List<CapturedApiCall> peeked = RouteDsl.peekCaptured(page);

// 消费式：取走后清空（第二次返回空）
List<CapturedApiCall> dumped = RouteDsl.dumpCaptured(page);

采集 → 回放（把真实响应变成 Mock）

// 先采集（MONITOR 默认采集），再把某条记录直接作为 Mock 规则
CapturedApiCall captured = RouteDsl.peekCaptured(page).get(0);

RouteDsl.on(page)
    .api("/api/users")
    .mock().fromCaptured(captured)      // 注册期即时快照，不怕采集器清理
    .register();

停止 / 清理

需求用法影响范围
只停某个 pattern 的某能力RouteDsl.stopMonitor(page, "/api/users")（或 stopMock/stopModify/stopDelay/stopApi）该 pattern 该能力
注销自己注册的规则持有 register() 返回的 AutoCloseable 调 close()该句柄覆盖的规则
清空该 context 全部规则，保留 context 与登录态RouteDsl.clearRules(page)（返回退役条数）该 context 规则
清空全部 context 的规则RouteDsl.clearRulesAll()所有 context
关闭并释放某 context 的 Route 运行时RouteDsl.clear(page)该 context 整个 runtime

能力组合矩阵（能不能一起用）

MONITORMODIFYDELAYMOCK业务场景状态
✓观测/断言真实响应✓
✓✓强制请求头后断言真实响应✓
✓✓static慢交付夹具✓
✓intercept真实响应改字段后断言✓
✓any改请求 + 决定响应✓
✓✓延迟释放改写后的请求✓
✓intercept慢交付"真实+改写"⚠ 已知限制
feature 模式语义（重要）：web 层在每个 scenario 结束（testFinished）会对 Context 调 clearContext，而 Route 的该挂点会关闭整个 per-context 运行时——所以默认 Route 规则不跨 scenario 保留（每个 scenario 起点 runtime 重建、规则为空），feature 模式也一样。需要"复用 Context、只清规则"时用 RouteDsl.clearRules(page)。
两条最易误用点：① MONITOR 断言 + static MOCK 时，断言对象是你伪造的夹具而非真实响应（合法，但易误判为"没生效"）；② interceptResponse() 与静态 status/body/headers 互斥。

9安全基线

  • 凭据一律环境变量注入（如 DBB_TEST_PASSWORD、CONFIG_MASTER_KEY），禁止入库。
  • 配置里的敏感值支持 ENC(<base64>) 透明解密（如 monitor.db.password）。
  • 日志出口强制脱敏；API 请求/响应日志默认关闭。
  • 截图默认「仅失败步、非全页」；报告推送前有凭据扫描门禁。

10FAQ

跑用例报浏览器找不到 / 起不来？
先安装浏览器：mvn exec:java -Dexec.mainClass=com.microsoft.playwright.CLI -Dexec.args="install chromium"。若公司有代理，配置 playwright.browser.download.http.proxy / https.proxy，或预置到 playwright.browsers.path。
Route 规则这个 scenario 生效，下个 scenario 就没了？
这是设计如此。每个 scenario 结束（testFinished）框架会关闭该 Context 的 Route 运行时，下个 scenario 重建、规则为空——feature 模式同样不跨 scenario 保留。需要"复用 Context、只清规则"用 RouteDsl.clearRules(page)；只想跑完某段就撤，用 register() 返回的句柄 close()。
Mock 没生效，页面还是走了真实接口？
逐条排查：① pattern 是否与实际 URL 匹配（注意通配 **）；② 匹配条件（method/header/query）是否过严；③ 是否用了 interceptResponse() 又同时设了静态 body（互斥，配置期应报错）；④ 规则是否已被 stop* / close() / scenario 收尾清掉。
MONITOR 断言"失败"了，但接口明明正常？
若同一 pattern 同时有 static MOCK，MONITOR 断言的对象是你伪造的夹具，不是真实响应。要么改断言期望（对齐夹具），要么改用 interceptResponse() 保留真实响应。
并行跑时随机 401 / 被踢登录？
这是同身份并发被 SSO 互踢。保持 serenity.playwright.concurrent.partition.enabled=auto（按身份分区互斥）与 …partition.fail.closed=true（闸门超时即判失败，不静默串行）。
日志太吵 / 想定位卡在哪一步？
默认 framework.verbose.logging=false 只留关键日志；排查时打开它，或调 serenity.playwright.hang.watchdog.interval.ms（用例跑太久时周期性打印线程栈，定位无日志的阻塞点）。
报告在哪？怎么只跑某几个用例？
报告默认输出到 target/site/serenity。选择性执行用标签：在 feature 打 @smoke，然后 mvn verify -Dtags="@smoke"；默认跑 not @skip。
改了配置不生效？
记住优先级：-D > 环境变量 > 配置文件 > 默认值。别用 clearProperty 期望回落（不保证）；要用 -D 显式覆盖。route 采集三键是环境变量优先，别搞反。
DELAY 怎么写？
DELAY 段没有 register()，用 RouteDsl.on(page).api("/api/slow/**").delay(3).done().start();（单位是秒）。随机延迟：.delay(1).randomDelay(1,5)。单请求上限 30 秒。
Mock 二进制响应时文件损坏？
用 mockBody(byte[])（字节保真通道），不要用 mockBody(String) 走文本往返。fromCaptured(...) 对非文本体会自动走字节保真通道。
元素定位该用什么？
优先 @RoleElement（角色 + NLS，或 text/label/testId 等语义），比 CSS/XPath 更抗重构、可访问性更友好。不要在 Step 里直接持有 Playwright Locator（框架架构门禁禁止类型泄漏）。
怎么快速生成页面对象代码？
用 pw-codegen 的交互式拾取器点选页面元素，自动抓取 a11y role/name 并生成带 @RoleFile + @RoleElement 的 Page 类草稿（含 NLS key），人工 review 后合入。

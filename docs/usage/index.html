DBB 自动化测试框架 · 使用指南

基于 Playwright 驱动浏览器、Serenity BDD + Cucumber 组织用例与报告，内置声明式网络拦截（monitor / mock / modify / delay）与日志脱敏的企业级多模块测试框架。

JDK 21Maven 多模块 Playwright 1.62Serenity 4.3.4 Cucumber 7.34JUnit 4

1框架概览

这是一套「UI + 接口」一体的自动化测试框架。你用 Cucumber 写业务用例（Gherkin），用 Playwright 操作页面，用框架自带的 Route DSL 拦截/伪造网络请求，Serenity 自动生成图文报告。

2工程结构（用例工程约定的目录）

框架仓库只放「能力模块」；你的业务用例放在测试工程里。约定目录如下：

test-automation/
├─ pom.xml                          # 依赖框架各模块
└─ src/test/
   ├─ resources/
   │  ├─ features/                  # Gherkin 用例（.feature）
   │  │  └─ web/login_dbb.feature
   │  ├─ nls/                       # 多语言元素名（@RoleFile 指向）
   │  ├─ mocks/                     # Mock 夹具模板（mockBodyFromFile 读 classpath）
   │  ├─ payload/                   # 接口测试请求体
   │  ├─ config/                    # application.conf / *.conf
   │  └─ serenity.conf              # 框架配置（见第 10 节）
   └─ java/…/tests/
      ├─ CucumberTestRunnerIT.java  # 运行入口（@RunWith(CucumberWithSerenity)）
      ├─ glue/                      # Glue 层：步骤绑定（@Given/@When/@Then）+ 钩子（@Before/@After）
      ├─ steps/                     # Steps 层：业务编排（@Step），调用页面对象
      └─ pages/                     # Page 层：页面对象（extends AbstractManagedPage）
约定优于配置：feature 放 src/test/resources/features；Runner 用 @CucumberOptions(glue = {"…tests.glue", "…tests.api.steps"}) 指定 Glue 包的扫描范围；用例筛选用标签（tags）。

4如何写用例

一个用例由四层组成：Feature（做什么）→ Glue（怎么绑定）→ Steps（怎么做）→ Page（在哪个页面做）。各层各司其职：Gherkin 只讲业务，Glue 只做绑定与钩子，Steps 写业务编排，Page 只描述页面。

① Feature 文件（Gherkin）

用业务语言描述场景，不写任何实现细节。中文/英文皆可，团队统一即可。

@smoke
Feature: 用户管理

  Background: 打开用户列表
    Given 打开用户列表页

  Scenario: 查询用户列表
    Then 用户列表应包含 3 条记录

  Scenario: 查询不存在的用户
    When 查询用户 ID 999
    Then 结果应为空

  @route
  Scenario: 列表接口异常时页面给出提示
    Given 列表接口返回 500
    When 刷新用户列表页
    Then 页面应显示"加载失败"提示

② Glue 层（把 Gherkin 步骤绑到代码）

放在 glue/ 包（Runner 的 glue= 就是指向它）。Glue 只做两件事：用 @Given/@When/@Then 绑定步骤文本，并通过 Serenity 的 @Steps 把活委派给 Steps 层。它不写业务、不碰选择器。

package com.hsbc.cmb.hk.dbb.automation.tests.glue;

import com.hsbc.cmb.hk.dbb.automation.framework.web.annotations.AutoBrowser;
import com.hsbc.cmb.hk.dbb.automation.tests.steps.UserListSteps;
import io.cucumber.java.en.*;
import net.serenitybdd.annotations.Steps;

@AutoBrowser(verbose = true)                  // 浏览器自动托管：本场景用完即收
public class UserListGlue {

    @Steps                                    // Serenity 注入 Steps 实例（并纳入报告）
    private UserListSteps userListSteps;

    @Given("打开用户列表页")
    public void openUserList() { userListSteps.openUserList(); }

    @When("查询用户 ID {int}")
    public void queryUser(long id) { userListSteps.queryById(id); }

    @Then("用户列表应包含 {int} 条记录")
    public void shouldContain(int count) { userListSteps.shouldContain(count); }

    @Given("列表接口返回 {int}")
    public void listApiReturns(int status) { userListSteps.listApiReturns(status); }
}

场景钩子（@Before/@After）同样放在 Glue 包，用于场景级隔离（绑定用例上下文、清理残留、释放资源）：

public class UserHooks {
    @Before(order = Integer.MIN_VALUE)   // 最早执行：先校验无残留，再绑定本用例上下文
    public void before(Scenario scenario) { ScenarioContext.begin(scenario.getId()); }

    @After(order = Integer.MAX_VALUE)    // 最晚执行：解绑并断言已释放
    public void after(Scenario scenario) { ScenarioContext.end(scenario.getId()); }
}

③ Steps 层（业务编排）

放在 steps/ 包，方法上打 @Step（会进 Serenity 报告）。Steps 只写业务动作：调用页面对象 + 断言；页面对象由 PageObjectFactory.getPage(...) 获取，框架按当前线程注入已装饰的 Page（构造期不建浏览器）。

package com.hsbc.cmb.hk.dbb.automation.tests.steps;

import com.hsbc.cmb.hk.dbb.automation.framework.route.dsl.RouteDsl;
import com.hsbc.cmb.hk.dbb.automation.framework.web.page.factory.PageObjectFactory;
import com.hsbc.cmb.hk.dbb.automation.tests.pages.UserListPage;
import net.serenitybdd.annotations.Step;
import org.assertj.core.api.Assertions;

public class UserListSteps {

    private final UserListPage userListPage = PageObjectFactory.getPage(UserListPage.class);

    @Step
    public void openUserList() {
        userListPage.navigateTo("/users");
    }

    @Step
    public void queryById(long id) {
        // 页面对象也提供 element(selector) 现场定位（返回 PageElement）
        userListPage.element("[data-user-id='" + id + "']").click();
    }

    @Step
    public void shouldContain(int count) {
        userListPage.waitForRows(count);
        Assertions.assertThat(userListPage.userRows.size()).isEqualTo(count);
    }

    @Step
    public void listApiReturns(int status) {
        RouteDsl.on(userListPage.getPage())      // 绑当前页面所在 context
            .api("/api/users")                   // 端点即可，无需通配符（见第 7 节）
            .mock().status(status).body("{\"error\":\"boom\"}").contentType("application/json")
            .done().start();
    }
}
参数化步骤：Cucumber 内置 {int}、{string}、{word} 等占位符，直接映射为 Glue 方法参数，无需手工解析。

④ 在 Steps 里做接口拦截（Route）

需要「让接口返回 500 看页面表现」时，就在对应 Steps 方法里用 RouteDsl 注册规则（完整 DSL 见第 7 节）——上面的 listApiReturns(int) 即是示例。原则：Glue 只绑定步骤文本，Route（以及页面操作）写在 Steps 里；若场景需要，也可直接写在 Glue（同一场景/线程内同样生效）。

5页面对象与元素定位

页面对象继承 AbstractManagedPage（框架提供的组合式轻量基类），把"元素"声明成字段。运行期框架自动绑定当前线程的 Page/Context，Steps 直接操作字段，不接触 Playwright 原生 Locator。

最小页面对象

package com.hsbc.cmb.hk.dbb.automation.tests.pages;

import com.hsbc.cmb.hk.dbb.automation.framework.web.page.base.AbstractManagedPage;
import com.hsbc.cmb.hk.dbb.automation.framework.web.page.element.Element;
import com.hsbc.cmb.hk.dbb.automation.framework.web.page.element.PageElement;
import com.hsbc.cmb.hk.dbb.automation.framework.web.page.element.PageElementList;
import com.hsbc.cmb.hk.dbb.automation.framework.web.page.element.RoleElement;
import com.microsoft.playwright.options.AriaRole;

@RoleFile("nls/users.nls.json")            // 本页多语言元素名（类级声明一次）
public class UserListPage extends AbstractManagedPage {

    @RoleElement(role = AriaRole.HEADING, level = 1, key = "title")
    public PageElement title;              // 角色 + NLS：跨语言、抗重构

    @RoleElement(role = AriaRole.LISTITEM)
    public PageElementList userRows;       // 一组元素（动态查询可见元素）

    @Element("[data-user-id]")             // CSS / XPath 兜底（无合适角色 / NLS 时）
    public PageElement firstUserRow;

    @RoleElement(role = AriaRole.BUTTON, key = "refresh")
    public PageElement refreshButton;

    public void waitForRows(int expected) {
        userRows.waitForCount(expected, 30);   // 框架级等待（带重试 / 诊断）
    }
}
业务页继承 AbstractManagedPage 即可，元素用 @Element / @RoleElement 注解绑定；页面对象统一由 PageObjectFactory.getPage(XxxPage.class) 获取。

PageElement 常用操作

字段声明为 PageElement 后，直接链式调用（每一步都带框架的重试 / 诊断 / 失败截图）：

分类方法
动作click() · jsClick() · doubleClick() · rightClick() · hover() · focus() · press(key)
输入fill(text) · type(text) · clear() · clearAndSetValue(text) · selectByVisibleText(text) · selectByValue(v)
状态判断isVisible() · isEnabled() · isDisabled() · isChecked() · isEditable() · exists()
读取getText() · getTextRaw() · getValue() · getAttribute(name) · getInnerHtml()

PageElementList 另有：size() / size(sec) · waitForCount(n, sec) · first() / last() / get(i) · isEmpty() · forEachSafe(action)。

定位策略：优先「角色 / 语义」，不要写 CSS/XPath

@RoleElement 支持两类策略，二选一（设置语义属性后 role 被忽略）：

策略写法等价于
角色 + 多语言@RoleElement(role = AriaRole.BUTTON, key = "signIn")按角色 + NLS 名称，支持多语言
@RoleElement(role = AriaRole.BUTTON, name = "Sign in")按角色 + 字面名称（NLS 无 key 时用）
语义定位@RoleElement(text = "Submit")getByText
@RoleElement(label = "Username")getByLabel（定位关联 input 控件）
@RoleElement(placeholder = "搜索")getByPlaceholder
@RoleElement(testId = "user-row")getByTestId
@RoleElement(altText = "Company logo")getByAltText
@RoleElement(title = "帮助")getByTitle
CSS / XPath@Element(".row") / @Element("//button")原始选择器兜底（无合适角色 / 语义时）；同样享受框架的重试与诊断

两类注解分工：@RoleElement 走「角色 / 语义」，最抗重构、可访问性最友好；@Element 直接给 CSS 或 XPath（以 // 或 xpath= 开头即按 XPath 解析），作为兜底。

进阶属性（@RoleElement）

属性取值说明
level1–6，默认 0仅 AriaRole.HEADING 生效：限定标题层级（对应 h1–h6 / aria-level）；0 = 不限层级。用于再收窄标题定位，且不依赖 DOM 结构与文案
exacttrue(默认) / false名称 / 文本是否精确匹配（大小写敏感）；对 testId / label 不生效
disabledANY(默认) / YES / NO按可访问「禁用」态过滤（对应 getByRole(role).setDisabled(...)）
pressedANY / YES / NO按 aria-pressed 过滤（折叠触发、收藏开关等切换按钮）
expandedANY / YES / NO按 aria-expanded 过滤（菜单、树节点、手风琴）
frame{"iframe[name=\"x\"]"}iframe 嵌套路径，自顶向下按层声明；主框架内的元素留空。运行时逐层 frameLocator 包裹，否则在主框架上找不到元素
key / name字符串key = NLS 键（多语言）；name = 字面可访问名（NLS 里没有该键时才用）
file路径本字段单独指定 nls 文件（默认沿用类级 @RoleFile）
description文本仅用于日志与报错信息，不影响定位
跨源 iframe 限制：frame 路径只能定位同源 iframe 内的元素。跨源（不同域名 / 协议 / 端口）iframe 受浏览器安全策略限制，框架无法跨边界定位其内部元素——这类元素需改用其他方式（如单独驱动该 iframe 对应的页面 / 直接走接口校验）。拾取元素时跨源 iframe 内的元素也会被自动跳过（见第 6 节注意事项）。
三态怎么理解：Playwright 的 setXxx() 只有 true / false 两态（不调用 = 不限定），框架用三态表达得更明确 —— ANY = 不限定（匹配任意状态）；YES = 只匹配「处于该状态」的元素；NO = 只匹配「不处于该状态」的元素。 例：@RoleElement(role = AriaRole.BUTTON, name = "Submit", disabled = RoleElement.State.NO) 只定位可用按钮。
推荐：优先用 pw-codegen 的交互式拾取器点选元素，自动生成 @RoleElement 草稿（含 NLS key），人工 review 后合入。

6拾取元素（交互式拾取器）

框架提供 pw-codegen 模块的交互式拾取器（RoleElementPicker）。它的使用体验类似 Playwright 的 page.pause()：在有头浏览器里点选你想操作的元素，它自动抓取被点元素的 a11y role / name，并生成带 @RoleFile + @RoleElement 的页面对象草稿。与 page.pause() 的关键区别：pause 录出来是平铺在测试方法里的 locator(...).click() 脚本，选择器与业务步骤耦合；这边拾取产物直接落到页面对象字段，业务 step 只调语义方法——选择器只在 Page 类出现一次，UI 改版只改 Page。

跨源 iframe 限制（重点）：拾取器无法拾取跨源 iframe 内的元素——跨源（不同域名 / 协议 / 端口）iframe 受浏览器安全策略限制，不经主框架，会被直接跳过。若需操作跨源 iframe 内的控件，请改用其他方式（单独驱动该 iframe 对应的页面 / 直接接口校验）。同源 iframe 不受影响（用 frame 属性声明嵌套路径即可，见第 5 节）。

前置条件（必须满足，否则拾取不会生效）

条件说明
有头浏览器必须在 headed 模式下运行（能看到浏览器窗口）；无头模式无法人工点选。
开启开关启动 JVM 时加 -Ddbb.codegen.enabled=true。该开关默认 false——关闭时框架热路径不触碰 codegen，避免给自动化测试引入无关开销。
页面已导航调用前页面须已 navigateTo 到目标页（拾取的是"当前可见"的元素）。
本地使用拾取器是本地开发辅助工具；它会自动探测 CI 环境变量（Jenkins / GitHub Actions / GitLab CI / TeamCity 等），在 CI 中自动跳过并直接返回空列表，不会卡住等待人工交互。

两种用法

① 打开常驻控制面板（最贴近 page.pause() 的体验，推荐）

// 在 Steps / 调试代码里调用；page 为当前线程的 Page
RoleElementPicker.openPanel(page, "nls/login.nls.json");

调用后浏览器侧浮出一个 inspector 面板，控件含义：

控件作用
▶ 开始拾取 / ⏹ 停止并生成空闲时显示「开始拾取」（绿），点后进入点选模式，在页面点击目标元素；拾取中变「停止并生成」（橙），再点即退出点选、按已点元素生成代码填入面板。
📋 复制代码一键复制面板中的代码。
⏻ 终止运行抛出 PickerAbortedException，中断调用方后续代码（如自动登录）。
✕ 关闭面板退出面板，结束阻塞。

点「开始拾取」→ 在页面上点选元素（可跨弹窗 / 新标签页，拾取器会跟随）→ 点「停止并生成」→ 在面板里复制代码。生成物含 页面类 + 步骤类 + 断言类，跨页（弹窗等）会各自生成对应的页面类。

② 代码内直接调用（程序化）

// 拾取并直接写入源码文件（outputDir 为源码根，如 src/test/java）
RoleElementPicker.pickAndWrite(page, "src/test/java",
        "com.xxx.tests.pages", "LoginPage", "nls/login.nls.json");

// 拾取并弹出可复制代码面板（拾取完直接弹框，复制即用）
RoleElementPicker.pickAndShow(page, "com.xxx.tests.pages", "LoginPage", "nls/login.nls.json");
拾取模式：当前只有手动模式（点哪个元素拾哪个），拾取器只采集你主动点选的少数控件——非常适合页面冗杂、只需其中几个元素的场景。

常用 API（方法签名速查）

所有方法都在 com.hsbc.cmb.hk.dbb.automation.framework.web.page.scan.RoleElementPicker 下，静态调用。先拿到当前线程的 Page：在 Page 对象里调用 getPage()，或在 Steps 里用 getPage()。

方法作用
openPanel(Page, String... nlsFiles)打开常驻面板（推荐）；类名由当前 URL 自动派生。点「停止并生成」后面板直接展示可复制的页面类 + 步骤类 + 断言类代码。
pickAndWrite(Page, String outputDir, String packageName, String pageClassName, String... nlsFiles)拾取完成后直接把源码写到 outputDir（如 src/test/java）。
pickAndShow(Page, String packageName, String pageClassName, String... nlsFiles)拾取完成后弹出可复制代码面板（不落盘）。
CI 自动跳过：以上所有入口在检测到 CI 环境变量（Jenkins / GitHub Actions / GitLab CI / TeamCity 等）时会直接跳过或返回空，不会卡住等待人工交互——本地有头浏览器 + -Ddbb.codegen.enabled=true 才真正生效。

NLS 反查（让生成的 key 直接用真实多语言名）

传入 nls 文件路径后，拾取时会用被点元素的 a11y name 反查该表；命中则生成的 @RoleElement 直接复用真实 key，未命中回退为 slug。nls 文件格式（按语言分组，文本值 → key）：

// nls/login.nls.json
{
  "en-US": { "signIn": "Sign in", "welcomeHeader": "Welcome to Business" },
  "zh-CN": { "signIn": "登入",  "welcomeHeader": "欢迎使用商务理财" }
}

把该路径作为 openPanel / pickAndWrite 的最后一个（可变）参数传入即可，多个 nls 文件会合并反查。

生成的产物长什么样

  • 页面类：带类级 @RoleFile("nls/login.nls.json")，字段为 @RoleElement(...)，字段名按 a11y role 自动加语义后缀（button→Btn、link→Link、textbox→Input、checkbox→Chk 等）。

7Route 网络拦截怎么用

Route 让你在不改后端的前提下，声明式地观测、伪造、改写、延迟浏览器发出的 HTTP 请求。它挂在 BrowserContext 上，按 context 隔离。

四种能力（一规则一能力）

能力作用会不会影响请求
MONITOR观测：记录请求/响应，做状态码 / JSONPath / 体 / 表单断言否（fail-open，放行）
MOCK伪造响应：静态 body/status，或取真实响应后改字段是（交付你给的内容）
MODIFY_REQUEST改写请求：请求头 / method / 请求体字段是（后端看到的是改后的）
DELAY延迟放行：模拟慢网络否（只是晚点放行）
DELAY 只能「变慢」，不能「造超时」：它只是把真实请求推后 N 秒再放行，响应内容仍是真实后端的；它不会自己产生超时或失败。要测「接口超时 / 失败」，请用 MOCK 返回错误码，或把 DELAY 的延迟调到大于前端等待阈值，让前端自己超时。
注册失败的行为：MONITOR 注册失败只告警、不阻断用例（观测不该拖死业务）；MOCK / MODIFY_REQUEST / DELAY 注册失败会直接报错——因为它们会改变请求行为，规则没生效却继续跑会让断言口径失真。

基本骨架

.register() / .start() 都返回 AutoCloseable 句柄——推荐 try-with-resources，出作用域自动精确注销，不会漏 close()：

import com.hsbc.cmb.hk.dbb.automation.framework.route.dsl.RouteDsl;

try (AutoCloseable handle = RouteDsl.on(page)     // 也可 RouteDsl.on(context)
        .api("/api/users")                       // 端点即可，无需通配符（见下）
        .monitor()                               // 选择能力：monitor / mock / modifyRequest / delay
            .expectStatus(200)
            .expectJsonPath("$.length()", 3)
        .register()) {
    // ... 执行业务步骤，期间该规则生效 ...
}  // 出 try 块自动 handle.close()，规则精确注销

// 也可以手动持有句柄：AutoCloseable handle = ...register(); ...; handle.close();
// 句柄 close() 幂等；即使忘了 close，scenario 结束时框架也会随 Context 统一清理。
pattern 不用手写通配符：注册时框架会把端点前后各补一层 **（RoutePatterns.normalize），所以 .api("/api/users")、相对端点 .api("profile/list") 都能命中真实绝对 URL，语义近似「URL 包含该片段」。显式写 ** 结果相同，没必要写。
两种收尾写法完全等价：.register() 立即注册并返回句柄；级联写法 …done().start() 也返回同一个句柄。
DELAY 段只有 .done().start()：monitor() / mock() / modifyRequest() 段各自带一个 register()（可在段末直接提交），而 delay() 返回的 DelayDsl 没有 register() 方法，所以延迟规则必须用 .done() 收段、再由根 .start() 统一提交，即 .api(p).delay(3).done().start();。多规则级联时，「每条 .done()、最后一句 .start()」也是推荐写法。

匹配条件（收窄规则命中范围）

在 api(pattern) 之后、能力之前或之后链式声明，多个条件同时满足才命中：

RouteDsl.on(page)
    .api("/api/login")
        .onlyApi()                    // 只匹配 xhr/fetch
        .matchMethod("POST")          // 精确 method
        .matchHeader("X-Env", "sit")  // 请求头精确
        .matchQuery("locale", "zh_CN")// query 精确
        .matchContentType("json")     // content-type 包含
        .matchBodyRegex(".*username.*")// 请求体正则
        .onlyMainFrame(true)          // 只主框架（默认）
    .mock()…

条件不满足的请求自动 fallback 到下一个匹配的规则，不会"吞掉"请求。

8Route 实战配方

MONITOR观测并断言真实响应

RouteDsl.on(page)
    .api("/api/users")
    .monitor()
        .expectStatus(200)
        .expectJsonPath("$[0].role", "USER")
        .expectBodyContains("Alice")     // 文本/XML/HTML 均可
        .timeout(10)                     // 断言等待窗口（秒，0=不超时）
    .register();
默认即采集：.monitor() 段默认记录请求/响应（响应体按 64 KiB 截断）。要关闭用 .capture(false) / .captureBody(false)。

MOCK静态伪造响应

RouteDsl.on(page)
    .api("/api/auth/login").onlyApi().matchMethod("POST")
    .mock()
        .status(200)
        .body("{\"token\":\"mock-token\",\"message\":\"ok\"}")
        .contentType("application/json")
        .header("X-Mocked", "true")
    .register();

也支持从 classpath 读模板、对象转 JSON、二进制保真：

// 读 classpath 模板 + 覆盖字段
.mock().mockBodyFromFile("mocks/login-template.json", Map.of("token", "t-x"));
// 对象自动转 JSON
.mock().mockBody(Map.of("code", 0, "msg", "ok"));
// 二进制（图片 / protobuf / gzip）——逐字节保真，不走字符串往返
.mock().mockBody(new byte[]{1,2,3}).contentType("application/octet-stream");

MOCK拦截真实响应后改写

// 取上游真实响应，改字段后再交给前端
RouteDsl.on(page)
    .api("/api/users")
    .mock().interceptResponse()
        .replaceField("$[0].name", "MOCKED")
        .replaceFields(Map.of("$[1].role", "ADMIN"))
    .register();

// 条件改写：仅当 status 为 PENDING 时才把 status 改成 SHIPPED
RouteDsl.on(page)
    .api("/api/users")
    .mock().interceptResponse()
        .when("$.status", "EQUALS", "PENDING").thenSet("$.status", "SHIPPED")
    .register();
互斥规则：interceptResponse()（取真实响应）与静态 status/body/header 不能同时用，配置期即报错。

MODIFY_REQUEST改写请求

RouteDsl.on(page)
    .api("/api/users")
    .modifyRequest()
        .setRequestHeader("X-Env", "mock")
        .removeRequestHeader("X-Debug")
        .modifyRequestBody("$.role", "ADMIN")        // JSONPath：存在即改，缺失即建
        .addRequestBodyField("$.tags[]", "vip")
        .modifyFormField("channel", "app")           // 表单（urlencoded）
    .register();

// 改 method（内部走 fetch+fulfill）
.modifyRequest().modifyMethod("PUT")

DELAY模拟慢网络

// 固定延迟 3 秒后放行（单位：秒）
RouteDsl.on(page).api("/api/slow").delay(3).done().start();

// 随机延迟：每次请求在 [1,5] 秒内随机
RouteDsl.on(page).api("/api/pay").delay(1).randomDelay(1, 5).done().start();
DELAY 只能用 .done().start() 收尾（DelayDsl 没有 register()）。单请求延迟上限 30 秒。它只延迟放行，不会造超时。

采集数据：查看与消费

// 非消费式：随时看该 context 采集到了什么（幂等）

// 消费式：取走后清空（第二次返回空）

采集 → 回放（把真实响应变成 Mock）

    .api("/api/users")

停止 / 清理

需求用法影响范围
只停某个 pattern 的某能力RouteDsl.stopMonitor(page, "/api/users")（或 stopMock/stopModify/stopDelay/stopApi）该 pattern 该能力
注销自己注册的规则持有 register() 返回的 AutoCloseable 调 close()该句柄覆盖的规则
同一 scenario 内清空该 context 全部规则（保留 context，不关 context、不收尾）RouteDsl.clearRules(page)（返回退役条数）该 context 规则
清空全部 context 的规则RouteDsl.clearRulesAll()所有 context
关闭并释放某 context 的 Route 运行时RouteDsl.clear(page)该 context 整个 runtime

能力组合矩阵（能不能一起用）

MONITORMODIFYDELAYMOCK业务场景状态
✓观测/断言真实响应✓
✓✓强制请求头后断言真实响应✓
✓✓static慢交付夹具✓

规则生命周期（重要）：每个 scenario 结束时框架会自动清理 Route 规则——所以 Route 规则不跨 scenario 保留。同一 scenario 内若想换一批规则，用 RouteDsl.clearRules(page)，随后重新 register()；只想跑完某段就撤，用 register() 返回的句柄 close()（或 try-with-resources 自动关）。

9接口测试（REST Assured）

pw-api-core 基于 REST Assured 封装，提供「声明式配置 + 语义化断言」的接口测试能力，与 Web 用例共用同一套 Serenity + Cucumber 基建。适合纯接口用例，或 Web 用例里需要直连后端做数据准备 / 结果校验的场景。

测试分层

与 Web 用例一致的四层：Feature（Gherkin）→ Glue（步骤绑定）→ Steps（持有 BaseStep 的步骤类）→（接口用例不写 Page）。接口用例直接操作 BaseStep，不需要页面对象；框架不要求 Steps 继承任何基类。

Feature: 用户接口
  Scenario: 查询用户列表
    Given an entity with "routedemo"           # 创建并持有 BaseStep
    When I set endpoint to "/api/users"
    And I send GET request
    Then response field "$.length()" should be 3
    And response body should match JSON schema "schemas/users.json"

创建 / 取用共享 BaseStep（ApiTestContext）

同一个 scenario 内的多个 step 类需要共享同一个 BaseStep（entity 配置、请求参数、响应状态都挂在它身上）。框架在 pw-api-core 内置了 ApiTestContext，提供 scenario 级共享：开头用 init() 创建一次，后续 step 直接 baseStep() 取用，场景结束时由框架自动复位，无需手写清理钩子。

import com.hsbc.cmb.hk.dbb.automation.framework.api.core.step.ApiTestContext;

// —— scenario 开头（EntitySteps 的 "Given an entity with ..."）——
ApiTestContext.init();                       // 动态配置（手动 setBaseUri / setEndpoint）
ApiTestContext.init("routedemo");            // 带实体配置（从 routedemo.conf 加载 baseUri / 端点）
ApiTestContext.init("routedemo", "dev");     // 再叠加环境覆盖

// —— 其余任意 step 类里直接取用同一个实例 ——
BaseStep step = ApiTestContext.baseStep();
业务侧不要再自己包持有类、也不要再手写 @After 清理：ApiTestContext 已随框架发布，scenario 结束时由框架统一复位，跨场景不会串扰。若 baseStep() 抛 IllegalStateException，说明本场景漏写了 Given an entity with ...。

低层工厂（TestServices，了解即可）

业务代码一般用上面的 ApiTestContext；保留三种形态备查：

import com.hsbc.cmb.hk.dbb.automation.framework.api.core.services.TestServices;
import com.hsbc.cmb.hk.dbb.automation.framework.api.core.step.BaseStep;

BaseStep step = TestServices.initialize().withEntity("routedemo").baseStep();   // 带实体
BaseStep step = TestServices.initialize().withEntity("routedemo").withEnv("dev").baseStep();
BaseStep step = TestServices.initialize().baseStep();                          // 动态配置

实体配置文件（{entityName}.conf）

把各接口的 path / 默认头 / 参数 / 请求体集中声明在 classpath 下的 {entityName}.conf（或 .properties），运行时用 loadEndpointConfig(name, method) 一键加载。仓库自带的 routedemo.conf 对应 route-demo-service 靶场（http://localhost:8888/demo），可直接拿来练手：

# routedemo.conf（HOCON）—— 靶场实际端点
api.base.uri.default = "http://localhost:8888/demo"
headers.Accept      = "application/json"

end-points {
  listUsers   { get  { path = "/api/users" } }
  getUser     { get  { path = "/api/users/{id}" } }
  createUser  { post { path = "/api/users"  payload = "payloads/create-user.json" } }
  login       { post { path = "/api/auth/login" payload = "payloads/login.json" } }
  slow        { get  { path = "/api/slow/endpoint" } }
}

# Steps 里加载：把 listUsers.get 的全部配置一次性灌到 BaseStep
baseStep().loadEndpointConfig("listUsers", "get");
baseStep().getResource();
配置按 end-points.<name>.<method> 组织；name 支持点号分层（如 user.findById）。也支持动态配置（不声明实体，直接 setBaseUri / setEndpoint）。

多环境切换（dev / test / prod）

环境通过 withEnv("dev") 显式传入（线程级、并行安全），对应配置文件里的同名节点会合并到基础配置之上。合并规则是 HOCON 按 key 深合并：环境节点 > 实体 conf > application.conf，且粒度是单个配置项 / 单个 header——冲突的 key 由环境胜出，不冲突的通用 key 自动保留。所以你只需在环境节点里写「与通用不同的那些项」，其余继承。

# routedemo.conf（HOCON）
# —— 通用配置（所有环境共享）——
api.base.uri.default = "http://localhost:8888/demo"   # 靶场默认地址
headers.Accept       = "application/json"
headers.Content-Type = "application/json"

end-points {
  login  { post { path = "/api/auth/login" payload = "payloads/login.json" } }
  user   { get  { path = "/api/users" } }
}

# —— 环境节点：只写「与通用不同的项」——
# dev：baseUri 改成远端 dev 环境；Authorization 用固定 dev token
dev {
  api.base.uri.default = "https://api.dev.example.com"
  headers.Authorization = "Bearer dev-fixed-token"
}
# test：baseUri 改测试地址，且不设固定 token（靠用例里 login 动态注入）
test { api.base.uri.default = "https://api.test.example.com" }
# prod：baseUri 改生产地址，Authorization 设为生产 token
prod {
  api.base.uri.default = "https://api.prod.example.com"
  headers.Authorization = "Bearer prod-fixed-token"
}
合并结果示意（以 withEnv("dev") 为例）：api.base.uri.default = https://api.dev.example.com（环境覆盖）｜headers.Accept = application/json（继承通用）｜headers.Content-Type = application/json（继承通用）｜headers.Authorization = Bearer dev-fixed-token（环境覆盖）。可见 dev 只改了 baseUri 和 Authorization，其余通用 header 原样保留。
一个坑：环境节点只能「覆盖」不能「删除」通用项。HOCON 的合并只填缺失 key，不会移除通用配置里已有的 key。若通用已经写了 headers.X = "A"，想让某个环境「不带 X」，不能靠省略（省略会继承 A），只能把它覆盖成一个空值：headers.X = ""。需要彻底剔除时，建议把该 header 从通用区挪到各环境节点分别声明。
也支持运行参数 -Denv=dev 或环境变量 env=dev（由 EnvironmentUtils 解析）；但 withEnv 语义更明确、且不会污染 JVM 全局，并行下互不串环境。scenario 结束时 ApiTestContext 由框架自动复位，业务侧无需手写 @After 清理。

增删改查（CRUD）全要素示例

以「用户资源」为例，覆盖 method / header / query 参数 / 请求体 的组合。要点：

Steps 类不需要继承任何基类：框架只要求你拿到 BaseStep 实例（通过 TestServices.initialize()…baseStep()），示例里都是普通类。若你的业务工程自带 Steps 基类，按需继承即可，框架本身不强求。
  • method 由你调用的发送方法决定——框架没有 setMethod(...)，而是 getResource()(GET) / postPayload()(POST) / putPayload()(PUT) / patchPayload()(PATCH，部分更新) / deleteResource()(DELETE) 各自一个方法。
  • POST / PUT / PATCH 发前先设请求体（setRequestPayload 内联或 loadPayload 读文件）；GET / DELETE 通常不带 body。
  • header / query / body 都在「发送方法之前」调用，且每次发送都是当前实例的瞬时状态——换请求记得按需重设或清理（clearHeader() / clearQueryParams()）。
import com.hsbc.cmb.hk.dbb.automation.framework.api.core.step.ApiTestContext;

public class UserCrudSteps {
    private BaseStep step() { return ApiTestContext.baseStep(); }

    // 增：POST + 自定义 header + query 参数 + 请求体
    @When("创建用户")
    public void createUser() {
        BaseStep step = step();
        step.setEndpoint("/api/users");
        step.addRequestHeader("Content-Type", "application/json");
        step.addQueryParam("async", "true");                 // → ?async=true
        step.setRequestPayload("{ \"name\":\"tom\", \"age\":20 }");
        // 也可从文件加载请求体：step.loadPayload("payloads/user-create.json");
        step.postPayload();                                  // method = POST（带 body）
        step.verifyResponseStatusCode(201);
        step.verifyResponseJsonPath("$.name", "tom");
    }

    // 查：GET + query 参数（无 body）
    @When("查询用户列表")
    public void listUsers() {
        BaseStep step = step();
        step.setEndpoint("/api/users");
        step.addQueryParam("role", "admin");                 // → ?role=admin
        step.getResource();                                  // method = GET
        step.verifyResponseStatusCode(200);
        step.verifyJsonArrayLength("$.items", 3);
    }

    // 改：PUT + 路径里的 id + 请求体（用 JSONPath 改字段）
    @When("修改用户 {int}")
    public void updateUser(int id) {
        BaseStep step = step();
        step.setEndpoint("/api/users/" + id);
        step.addRequestHeader("Content-Type", "application/json");
        step.setRequestPayload("{ \"name\":\"tom\", \"age\":20 }");
        step.modifyFieldsInRequestPayload("$.age", 21);      // 改请求体里的 age 字段
        step.putPayload();                                   // method = PUT（带 body）
        step.verifyResponseStatusCode(200);
    }

    // 局部改：PATCH（同上，仅更新部分字段）
    @When("局部修改用户 {int}")
    public void patchUser(int id) {
        BaseStep step = step();
        step.setEndpoint("/api/users/" + id);
        step.setRequestPayload("{ \"age\":22 }");
        step.patchPayload();                                 // method = PATCH
        step.verifyResponseStatusCode(200);
    }

    // 删：DELETE + 路径里的 id（通常无 body）
    @When("删除用户 {int}")
    public void deleteUser(int id) {
        BaseStep step = step();
        step.setEndpoint("/api/users/" + id);
        step.deleteResource();                              // method = DELETE
        step.verifyResponseStatusCode(204);
    }
}
已有完整 URL 时：直接用 getFullUrl(url) / postFullUrl(url) / putFullUrl(url) / patchFullUrl(url) / deleteFullUrl(url)，会按 URL 自动解析 baseUri / endpoint / query 后发送，省去分步 setEndpoint / addQueryParam。

链路串联：提取返回值 + token 注入

一条业务链路（登录 → 取 token → 调目标 API → 取信息 → 再调）放在同一个 BaseStep 实例上：它持有 baseUri / headers / 上一次响应，所以登录后提取的 token 注入实例，后续请求自动带上；某响应里要被下一步用到的值，提取出来存到 Steps 字段，下一步直接用。

提取返回值两种方式： ① 推荐——JsonPath.read(step.getResponseJson(), "$.data.id")（用响应体字符串，类型无关、最稳）； ② 快捷——step.getValidatableResponse().extract().path("$.token")（REST Assured 原生）。 JSONPath 支持 $.data.id、data.items[0].name。
注意：每次发请求都会覆盖实例里的响应，提取要在「下一次请求之前」完成；跨 step 传递的业务值请存在 Steps 类字段（BaseStep 不自动存业务值）。

完整示例（链路串联 Steps 片段）

import com.hsbc.cmb.hk.dbb.automation.framework.api.core.step.ApiTestContext;
import com.hsbc.cmb.hk.dbb.automation.framework.api.core.step.BaseStep;
import com.jayway.jsonpath.JsonPath;

public class UserApiSteps {
    // 同一 scenario 内，所有 step 通过 ApiTestContext.baseStep() 拿到同一个实例
    private BaseStep step() { return ApiTestContext.baseStep(); }

    private String userId;   // 提取出来、给后续 step 用的信息

    @Given("登录并拿到 token")
    public void login() {
        BaseStep step = step();
        step.setEndpoint("/api/auth/login");
        step.addRequestHeader("Content-Type", "application/json");
        step.setRequestPayload("{ \"user\":\"alice\", \"pwd\":\"secret\" }");
        step.postPayload();                                              // ① 发登录

        String token = JsonPath.read(step.getResponseJson(), "$.token"); // ② 提取 token
        step.addRequestHeader("Authorization", "Bearer " + token);       // ③ 注入，后续自动带
    }

    @When("查询用户列表")
    public void listUsers() {
        BaseStep step = step();
        step.setEndpoint("/api/users");
        step.getResource();                                             // ④ 已带 Authorization

        userId = JsonPath.read(step.getResponseJson(), "$[0].id");      // ⑤ 提取依赖信息
    }

    @When("查看该用户详情")
    public void viewUser() {
        BaseStep step = step();
        step.setEndpoint("/api/users/" + userId);
        step.getResource();                                             // ⑥ 依赖第二步的 userId
    }

    @Then("请求成功")
    public void assertOk() {
        step().verifyResponseStatusCode(200);
    }
}
更省事：把 login / listUsers 的 path / payload / 固定 headers 声明在 conf 的 end-points 里，用 step.loadEndpointConfig("login", "post") 一次性灌好，再 postPayload()。动态 token 仍走 addRequestHeader。
跨场景清理已自动化：ApiTestContext 在 scenario 结束时由框架统一复位，业务侧不需要再写 @After 钩子去 clear()；若出现跨场景串扰，框架会在日志里打出残留告警。

12配置加解密与日志脱敏

12.1 配置值加密（ENC()）

密码 / token / API key 不要明文写进 serenity.properties。用框架自带的 AES-256-GCM 把它转成 ENC(base64)，框架在读取时透明解密——代码里拿到的还是明文，配置仓库里看不到。

第一步：先生成主密钥（32 字节，64 位十六进制；主密钥本身绝不能入库）：

openssl rand -hex 32

把主密钥按下面任一方式给框架（按顺序找，先命中的生效）：

  1. 环境变量 CONFIG_MASTER_KEY（CI 推荐）
  2. JVM 系统属性 -Dconfig.master.key=...
  3. 文件 ~/.dbb_automation_master_key（内容就是 64 位 hex，建议权限 600）

第二步：把明文加密成密文（用框架自带 CLI）：

java com.hsbc.cmb.hk.dbb.automation.framework.common.security.ConfigCipher encrypt "mySecretPwd123"
# 输出形如：ENC(AbCdEf...==)

第三步：写进配置，代码侧零改动：

monitor.db.password = ENC(AbCdEf...==)
# 读取端仍写 ConfigProvider.get("monitor.db.password")，拿到的就是明文
校验密文：java ...ConfigCipher decrypt "ENC(...)"。裸 Base64（不带 ENC() 前缀）也会被识别为密文；不是密文的串原样返回，对旧配置零侵入。

12.2 日志 / 报告自动脱敏

不需要你写任何代码——框架在所有数据出进程的出口（logback、Serenity 报告、monitor-failures.html、落库、落文件）前强制过一道脱敏，已经覆盖：

  • 按字段名：默认清单覆盖 password / token / secret / authorization / cookie / cvv / pan / 身份证 / 手机号 等（key 规范化后再比，access_token/access-token/AccessToken 都能命中）。
  • 按值形态：Luhn 校验的银行卡号、IBAN、HKID、大陆身份证（GB 11643 校验位）、护照、回乡证、统一社会信用代码、Bearer/JWT、URL 内嵌凭据——识别后整段定长掩码，不留前 6 位、不泄露长度。
  • 递归结构：JSON 树深度不限；XML、x-www-form-urlencoded、纯文本兜底都走自己的处理链。

追加你自己的敏感字段（默认清单不够时），在配置里加：

sensitive.data.extra.header.keys  = x-internal-token, x-api-key
sensitive.data.extra.body.keys    = customerPin, cvv2
sensitive.data.extra.query.keys   = sign, ts
API 请求/响应详细日志默认关（api.request.response.logging.enabled=false）；调试时临时打开即可，打开后也会先脱敏再打。

13安全基线

  • 凭据一律环境变量注入（如 DBB_TEST_PASSWORD、CONFIG_MASTER_KEY），禁止入库。
  • 配置里的敏感值支持 ENC(<base64>) 透明解密（如 monitor.db.password）。
  • 日志出口强制脱敏；API 请求/响应日志默认关闭。
  • 截图默认「仅失败步、非全页」；报告推送前有凭据扫描门禁。

14FAQ

跑用例报浏览器找不到 / 起不来？
先安装浏览器：mvn exec:java -Dexec.mainClass=com.microsoft.playwright.CLI -Dexec.args="install chromium"。若公司有代理，配置 playwright.browser.download.http.proxy / https.proxy，或预置到 playwright.browsers.path。
Route 规则这个 scenario 生效，下个 scenario 就没了？
这是设计如此。每个 scenario 结束时框架会关闭该 Context 的 Route 运行时，下个 scenario 重建、规则为空——这是默认的安全行为，不要手动跨 scenario 保留 Context 复用 runtime。同一 scenario 内想换规则可用 RouteDsl.clearRules(page)；只想跑完某段就撤，用 register() 返回的句柄 close()（或 try-with-resources 自动关）。
Mock 没生效，页面还是走了真实接口？
逐条排查：① pattern 是否与实际 URL 匹配（框架会自动补通配 **，写端点即可）；② 匹配条件（method/header/query）是否过严；③ 是否用了 interceptResponse() 又同时设了静态 body（互斥，配置期应报错）；④ 规则是否已被 stop* / close() / scenario 收尾清掉。
MONITOR 断言"失败"了，但接口明明正常？
若同一 pattern 同时有 static MOCK，MONITOR 断言的对象是你伪造的夹具，不是真实响应。要么改断言期望（对齐夹具），要么改用 interceptResponse() 保留真实响应。
日志太吵 / 想定位卡在哪一步？
默认 framework.verbose.logging=false 只留关键日志；排查时打开它，或调 serenity.playwright.hang.watchdog.interval.ms（用例跑太久时周期性打印线程栈，定位无日志的阻塞点）。
报告在哪？怎么只跑某几个用例？
报告默认输出到 target/site/serenity。选择性执行用标签：在 feature 打 @smoke，然后 mvn verify -Dtags="@smoke"；默认跑 not @skip。
改了配置不生效？
记住优先级：-D > 环境变量 > 配置文件 > 默认值。别用 clearProperty 期望回落（不保证）；要用 -D 显式覆盖。route 采集三键是环境变量优先，别搞反。
DELAY 怎么写？
DELAY 段没有 register()，必须用 .done().start()：RouteDsl.on(page).api("/api/slow").delay(3).done().start();（单位是秒）。随机延迟：.delay(1).randomDelay(1,5)。单请求上限 30 秒；它只延迟放行，不会造超时。
Mock 二进制响应时文件损坏？
用 mockBody(byte[])（字节保真通道），不要用 mockBody(String) 走文本往返。fromCaptured(...) 对非文本体会自动走字节保真通道。
元素定位该用什么？
页面对象继承 AbstractManagedPage；元素优先用 @RoleElement（角色 + NLS，或 text/label/testId 等语义），比 CSS/XPath 更抗重构；无合适角色/语义时才退回 @Element（CSS / XPath）。不要在 Steps 里直接持有 Playwright Locator。
怎么快速生成页面对象代码？
用 pw-codegen 的交互式拾取器点选页面元素，自动抓取 a11y role/name 并生成带 @RoleFile + @RoleElement 的 Page 类草稿（含 NLS key），人工 review 后合入。
